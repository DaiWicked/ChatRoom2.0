## 1. 这是什么

ChatRoom 2.0 是一款**面向局域网**的即时聊天工具。把几台在同一个网段里的电脑连起来，双击运行，几秒内就能看到谁也在用，然后直接开聊。

它的设计目标是三个"零"：

| | 说明 |
| --- | --- |
| **零部署** | 不需要服务器、不需要安装服务、不需要配置路由器 |
| **零账号** | 不需要注册、不需要手机号、不需要登录，起个昵称就能用 |
| **零依赖** | 不需要外网；整份程序就是一个 exe，拷过去就能跑 |

聊天内容不经过任何服务器，直接在电脑之间点对点传递，所以数据只留在参与的这几台电脑上，不会上传到云端。

**什么时候适合用它**：你需要和别人快速沟通，但既不想装一个服务端，也不想注册一个账号 —— 或者干脆没有外网。

## 2. 能用来做什么

| 场景 | 怎么用 |
| --- | --- |
| **机房 / 电子教室** | 同学之间互传消息、截图、笔记；老师机和学生机在同一网段即可 |
| **办公室内网** | 公司禁用公网 IM、或内外网隔离时，作为内网临时沟通工具 |
| **宿舍 / 合租房** | 几台电脑连同一个 Wi-Fi，就能互相发消息、传文件 |
| **临时会议、活动、比赛** | 参与者连上同一个 Wi-Fi，立刻形成一个"群"，不用互相加好友 |
| **断网 / 断外网的应急环境** | 只要局域网交换机还在工作，它就能用 |
| **不想留下云端记录的沟通** | 所有记录只存在本机，不经过任何第三方 |

**它擅长**：同一网段内几个人到几十个人的即时文字沟通、发截图、传小文件。

**它不适合**：跨网段 / 跨公网联系远方的人；传输密码、证件等敏感信息；要求"消息一定送达"的正式通知。

## 3. 主要功能

### 聊天

- **群聊广播**：一键把消息发给同一网段里所有在用的人，适合通知、公告、多人讨论。
- **一对一私聊**：点侧栏里的某个人，就进入和他的独立私聊。
- **会话彼此独立**：群聊和各条私聊**分开显示、互不混杂**，切换会话只看到这个会话的内容，不会把私聊和群聊混在一起。
- **文字 + 表情**：内置表情面板（Win7 上会自动换成符号表情，保证老系统也能正常显示）。

### 图片与文件

- **发图片**：选择图片后自动压缩再发送（机房带宽有限，对方收到的是清晰可用的小图）。
- **收图片**：自动保存到本机数据目录，点一下就能用系统看图程序打开。
- **发文件**：同一个 📎 按钮，程序按文件类型自动判断走图片还是文件通道；单个文件上限 200KB。
- **收文件**：气泡上显示文件名和大小，**点一下自己选保存位置**（默认停在「下载」），程序不会偷偷存到你不知道的地方。
- **安全提醒**：收到 `.exe / .bat / .cmd / .scr` 这类可执行文件时，文件名会标红并追加一条警告，提醒你先确认来源。

### 提醒与未读

- **侧栏红点 + 顶部徽标 + 托盘数字**三处联动，一眼看出有没有新消息、是谁发来的。
- **后台提醒小窗**：窗口最小化、被其他窗口盖住或收进托盘时，新消息会在屏幕右下角弹一个小提醒 —— **不抢焦点、不闪任务栏、没有声音**，3.5 秒自动收起，点一下就能跳回对应会话。
- **同一个人连续来消息只合并成一条"N 条新消息"**，不会刷出一堆窗口。
- **勿扰模式**：可以分别对群聊和私聊关闭弹窗提醒。

### 聊天记录

- **本地保存**：记录按会话分别存在本机，下次打开自动接着显示，并标出「以下为新消息」。
- **搜索**：`Ctrl+F` 随时在当前记录里搜关键词。
- **引用回复**：右键消息 → 引用回复，会在输入框里自动带上原文。
- **导出**：右键 → 导出聊天记录，存成 txt。
- **一键清空**：设置里可勾选"关闭时清空聊天记录"。

### 外观与操作

- **明亮 / 深色两套主题**，一键切换，切换时不用重启程序。
- **聊天区可换壁纸**，并可用滑杆调整磨砂（模糊）程度。
- **动效开关**：一个开关控制全部动画效果，喜欢干脆利落的可以关掉。
- **窗口置顶**、**记忆窗口位置和大小**（下次打开回到原位）。
- **托盘常驻**：关闭窗口只是收进托盘，双击图标随时唤回。

## 4. 快速上手

**第 1 步 · 拿到程序**
编译或获取 `ChatRoom.exe`（见 [§12 编译与运行](#12-编译与运行)）。

**第 2 步 · 放到同一网段的电脑上**
在每一台要参与聊天的电脑上运行一份。判断是否同网段：IP 前三段相同，例如都是 `192.168.3.x`。

**第 3 步 · 首次启动会要求注册**
填写昵称，并在验证框里**精确输入小写 `yes`**，才能点「进入聊天室」。之后启动不再弹出（设置里可以重置）。

**第 4 步 · 放行防火墙**
Windows 首次询问时，勾选**允许「专用网络」**。这一步不做，别人就看不到你。

**第 5 步 · 等几秒，互相出现**
双方每 3 秒互相广播一次在线状态，最多约 3 秒就能在左侧「在线用户」里看到对方。
聊天区底部会打印状态，正常应显示：`聊天服务已启动，端口 47060，本机 <你的IP>，昵称「<昵称>」`。

**第 6 步 · 开始聊**

- 点左侧的某个人 → **和他私聊**；
- 点左上角「📢 群聊广播」→ **发给所有人**；
- 点输入框右边的 📎 → **发图片或文件**；
- 点 😀 → **插入表情**。

**退出**：点 ✕ 只是收进托盘继续后台收消息；要真正退出，右键托盘图标 →「退出」。

```
├──────────────┼──────────────────────────────────────────────┤
│ 📢 群聊广播   │                                              │
│ ──────────── │   ┌────────────────┐                         │  消息区：按会话显示，可设置壁纸
│ 🟢 小明 ②    │   │ 对方发来的消息   │                         │
│ 🟢 小红      │   └────────────────┘                         │
│              │                    ┌────────────────┐          │
│  ↑/↓ 切换     │                    │ 我发出的消息     │          │
│  （只列在线）  │                    └────────────────┘          │
├──────────────┴──────────────────────────────────────────────┤
│  [ 输入框（Enter 发送） ]            😀   📎   [ 发送 ]        │  输入区：表情 / 图片·文件 / 发送
└──────────────────────────────────────────────────────────────┘
```

- **左侧**：当前在线的人（收不到心跳的人会自动从这里移除），以及「群聊广播」入口。

- **中间**：消息气泡。自己发的靠右、对方发的靠左，服务消息（上线/下线/系统提示）是居中的小胶囊。
- **底部**：输入框和发送按钮。
- **右下角**：后台收到消息时出现的小提醒窗。

## 8. 数据存在哪

所有数据都在**本机**，位置是：

```
%APPDATA%\ChatRoom\
```

| 文件 | 内容 |
| --- | --- |
| `chat_settings.ini` | 你的设置（昵称、主题、壁纸等） |
| `chat_history.txt` | 聊天记录 |
| `chat_history.1.txt` | 较早的归档记录（记录过多时自动轮转，总量不会无限增长） |
| `chat_images\` | 收到并保存下来的图片 |
| `wallpaper.*` | 你设置的聊天区壁纸 |

**想彻底清理**：退出程序后，直接删除 `%APPDATA%\ChatRoom` 整个目录即可。下次启动会当作首次使用，重新走注册流程。

**不经过服务器**：聊天内容、图片、文件都只在参与聊天的电脑之间直接传递，不经过任何第三方服务器，也不会上传到云端。

## 9. 使用须知

- **必须在同一网段**：判断方法是 IP 前三段相同（例如都是 `192.168.3.x`）。
  校园网、单位网络里常见的「客户端隔离」（AP 隔离）会禁止同网段设备互相通信，这种网络下程序无法工作。
- **首次运行要放行防火墙**，并选择「专用网络」，否则别人看不到你。
- **大家最好用同一个版本**：老版本不认识新版本发来的图片消息，可能只看到文字。
- **消息是明文传输的**：同一局域网内如果有抓包工具，内容是可以被看到的。请不要用它传密码、证件等敏感信息。
- **消息不保证送达**：底层用的 UDP 是"发出即不管"的协议。对方离线时消息不会补发，等对方上线后重发即可。
- **文件内容不长期保留**：收到的文件只在你点它保存时才会落盘，所以程序重启后再点旧的文件气泡，会提示"内容不在本机"，需要对方重发。
- **防刷屏处罚**：短时间内连续发送（5 秒内超过 8 条）会先被暂停发送 5 秒，再次触发暂停 10 秒；
  **继续刷屏会触发全屏处罚画面并强制重启本机**。请勿用它刷屏。
- **同一台电脑同时只能开一个**：再开一个会提示「小小聊天已在运行中」。想在单机上测试，请用两台电脑或虚拟机。
- **只支持 Windows**，且是 32 位程序（在 64 位 Windows 上正常使用）。

## 10. 常见问题

**Q：看不到别人 / 别人看不到我？**
依次检查：① 是否在同一网段（IP 前三段相同）；② 双方是否都放行了 Windows 防火墙的「专用网络」；
③ 是否用了同一个版本；④ 换一个不做"客户端隔离"的网络。

**Q：消息发出去了，对方没收到？**
对方可能已经离线（侧栏里看不到他）。UDP 不保证送达，等对方上线后重发一次即可。

**Q：提示「图片接收不完整」？**
图片是分块传输的，网络抖动时可能丢块。让对方重发一次；如果频繁出现，说明链路质量差，建议改用文字沟通。

**Q：表情显示成方块？**
Windows 7 没有彩色 emoji 字体。程序会自动改用符号表情，保证老系统上也能正常显示。

**Q：后台 / 最小化时没有提醒？**
检查设置里「收到新消息时弹窗提醒」是否被取消勾选；另外只有"当前没在看那个会话"时才会提醒，正在看的会话不会打扰你。

**Q：收到文件后点一下没反应 / 提示内容不在本机？**
收到的文件不会自动保存，重启程序后内容就没了，记录里只剩文件名和大小。让对方重发一次，然后在气泡上点一下选择保存位置。

**Q：怎么改昵称？怎么重新注册？**
设置里改昵称后保存即可；点「重置昵称」会清空记录并在下次启动时重新弹出注册界面。

**Q：能换聊天区背景吗？**
设置 →「聊天区壁纸」→ 选择图片，再用「模糊度」滑杆调磨砂程度（0 = 清晰，15 = 中等，30 = 很糊）。
注意滑杆调的是**模糊程度**，不是明暗。

**Q：怎么让聊天记录里不留下内容？**
设置里勾选「关闭时清空聊天记录」，或在退出后删除 `%APPDATA%\ChatRoom` 目录。

## 11. 技术概览

给需要了解实现的人：

| 项目 | 说明 |
| --- | --- |
| 技术栈 | C# / WPF，.NET Framework 4.7.2，x86；**无任何第三方库** |
| 通信方式 | 局域网 UDP 直连（广播 + 单播），端口 **47060**，无中心服务器 |
| 在线发现 | 每 3 秒互相广播一次心跳；8 秒收不到即视为离线 |
| 用户身份 | 以 IP 标识，昵称为显示名（无账号体系） |
| 消息形态 | 文字、图片（压缩为 JPEG 后分块传输）、文件（分块传输，≤200KB） |
| 可靠性 | UDP 不保证送达；分块数据重复发送 + 接收端按序号去重，收不齐时明确提示 |
| 数据落地 | 全部在本机 `%APPDATA%\ChatRoom` |

通信采用自定义的轻量二进制协议：数据报 = `4 字节包类型 + UTF-8 昵称 + 0x00 + UTF-8 正文`。

| 包类型 | 用途 |
| --- | --- |
| `CHAT` | 心跳 / 上线通告 |
| `GBRD` | 群聊文字 |
| `PMSG` | 私聊文字 |
| `CIMG` | 图片分块 |
| `CFIL` | 文件分块 |

设计上遵循"**只扩展、不修改**"：新增功能用新的包类型，不改动已有包格式，所以老版本收到不认识的数据报会自然忽略，不会崩溃。

## 12. 编译与运行

**环境要求**

- Windows 7 SP1 及以上
- .NET Framework 4.7.2（运行）；开发机另需 Developer Pack
- Visual Studio 2019 / 2022，勾选「.NET 桌面开发」工作负载

**编译**

用 Visual Studio 打开 `ChatRoom.sln`，选择 `Release` 生成；或命令行：

```powershell
& "<VS安装目录>\MSBuild\Current\Bin\amd64\MSBuild.exe" ChatRoom.csproj /t:Rebuild /p:Configuration=Release
```

产物是单个 `bin\Release\ChatRoom.exe`（约 340KB，无附带依赖，目标机只需装 .NET Framework 4.7.2）。

> 注意：**不要**用 `C:\Windows\Microsoft.NET\Framework\v4.0.30319\MSBuild.exe` 编译 —— 它自带的编译器版本过老，无法识别本项目使用的 C# 语法，必须用 Visual Studio 自带的 MSBuild。

**启动参数**

```bat
ChatRoom.exe --nick=小明
```

可在启动时指定昵称。

## 13. 项目背景与后续方向

本项目最初是 `Jiyuikiller2.0-Comprehensive-Restructuring` 中的一个子模块，现已拆分为**独立项目**继续发展。

**当前定位**：局域网内"打开就能聊"的轻量聊天室。

**后续方向**：在保留"无服务器、打开即用"这一核心体验的前提下，逐步向**类似 [Session](https://getsession.org/) 的隐私优先聊天软件**演进 —— 让聊天内容加密、让身份不再只是一个昵称、让消息可靠送达、让对端看不到你的 IP。这条路上的第一步通常是：给消息加上签名与端到端加密，并把当前"重复发送"的传输方式换成带回执的可靠传输。
